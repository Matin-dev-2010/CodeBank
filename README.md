**CodeBank** is a Windows desktop application for saving, organizing, searching, and managing reusable code snippets in a local SQLite database.

> The repository contains the application source code. A Windows installer is generated by the tagged-release workflow. It is not code-signed.

## Features

- Create, view, update, and delete code snippets.
- Organize snippets by category, programming language, and tag.
- Store a title, description, source code, language, category, tag, and visibility flag.
- Browse records in the main grid and category-specific lists.
- Use parameterized SQLite commands for data operations.
- Validate required fields in the service layer.
- Warn before clearing, navigating away from, or closing the editor when unsaved changes exist.
- Reuse an existing database instead of dropping user data during initialization.

## Build and run

1. Clone the repository:

   ```bash
   git clone https://github.com/Matin-dev-2010/CodeBank.git
   cd CodeBank
   ```

2. Open `CodeBank.sln` in Visual Studio.
3. Restore NuGet packages.
4. Select the `Release` configuration.
5. Build the solution and run the application.
6. Run the automated tests with `dotnet test CodeBank.Tests/CodeBank.Tests.csproj --configuration Release`.

You can also build from a Visual Studio Developer Command Prompt:

```powershell
nuget restore CodeBank.sln
msbuild CodeBank.sln /p:Configuration=Release
```

The GitHub Actions workflow uses the .NET Framework 4.6.1 reference-assemblies NuGet package so the project can be compiled on a hosted Windows runner.

## Data storage

The application stores its SQLite database at `%LOCALAPPDATA%\Matin-dev-2010\CodeBank\database.db`. On first launch after this update, if the new location does not yet contain a database, CodeBank copies the legacy `database.db` from the application directory. SQLite write-ahead and rollback journal sidecar files are copied when present. The original database is retained as a backup. Existing data in the new location is never overwritten. If both locations already contain a database, CodeBank deliberately does not merge them.

The schema initializer creates the `CodeFormFile` table and indexes only when they do not already exist. It does not drop the existing table or migrate arbitrary future schema changes.

**Back up `database.db` before replacing application files or experimenting with schema changes.** Do not commit personal databases or real user data to this repository.

## CI build

GitHub Actions restores NuGet dependencies, builds the solution in Release mode on Windows, runs the NUnit unit tests, and uploads the application build and test results as workflow artifacts. A separate tagged-release workflow packages a per-user Windows installer with Inno Setup.

## Known limitations

- The application currently uses a local SQLite database and has no synchronization or multi-user server.
- SQLite schema version tracking starts at version 1. A dedicated upgrade migration from version 1 to a future schema has not yet been implemented.
- Unit tests cover service validation and legacy database-file migration. Full UI automation and end-to-end database tests are still future work.
- The application targets .NET Framework 4.6.1; this is a legacy framework target and should be upgraded only with a deliberate compatibility plan.
- A Windows installer can be generated from a version tag. It is not code-signed; Windows SmartScreen may display an unknown-publisher warning.

These are documented follow-up areas, not features that should be assumed to exist. The automated tests do not yet replace manual Windows UI and end-to-end verification.
